# AI Document → Video — Web UI

A local, single-screen web app that wraps the whole pipeline:

1. **Upload** a PDF/DOCX document.
2. Click **Generate** → storyboard (`prompt_generation.py`) and images
   (`image.py`) run **locally**.
3. The video stage runs **automatically on Kaggle's free GPU** (Tesla T4) via the
   Kaggle API — no manual "Run all", no Google Drive step.
4. The finished video is downloaded back and shown for **preview + download**.

This replaces the old manual flow (run `main.py`, upload to Drive, open Colab,
click *Run all*, pick a language, download from the Colab runtime).

## How the Kaggle automation works

| Step | API call |
|------|----------|
| Upload `storyboard.json` + scene images as a private dataset | `dataset_create_new` / `dataset_create_version` |
| Push a generated, non-interactive notebook (language injected, GPU + internet on) | `kernels_push` |
| Wait for the GPU run to finish | `kernels_status` (polled) |
| Download the final video | `kernels_output` |

The notebook is generated by `notebook_builder.py` and mirrors the user's
working Kaggle notebook (SVD clips → gTTS narration → moviepy assembly), with the
`input()` language prompt replaced by an injected value and assets read from the
uploaded dataset.

## Setup

```bash
# from the repo root
pip install -r requirements.txt          # local generation stack (Ollama/SDXL/etc.)
pip install -r webui/requirements.txt    # web UI + Kaggle API
```

Local prerequisites (same as the CLI pipeline): **Ollama** running with
`llama3.2:3b`, and a GPU for SDXL image generation.

### Kaggle credentials (for the video stage)

The Kaggle account must be **phone-verified** (required for GPU + internet
kernels) and the client must be **`kaggle>=1.8.0`** — older clients cannot
authenticate Kaggle's current token system.
 
Kaggle now offers two credential styles; the app supports both.
 
**A. New access-token system (current Kaggle default).** Create a token at **kaggle.com → Settings → API → Create New Token**, then save the copied token to
`~/.kaggle/access_token` (a plain text file containing only the token string —
*not* a folder, not JSON):

mkdir -p ~/.kaggle
echo "PASTE_YOUR_TOKEN" > ~/.kaggle/access_token
chmod 600 ~/.kaggle/access_token         # Linux/macOS
export KAGGLE_USERNAME=your_username  

On Windows (PowerShell):
 
```powershell
Set-Content -Path $HOME\.kaggle\access_token -Value "PASTE_YOUR_TOKEN" -NoNewline
$env:KAGGLE_USERNAME = "your_username"
```
 
**B. Legacy key pair.** Place `kaggle.json` at `~/.kaggle/kaggle.json`, or set
`KAGGLE_USERNAME` + `KAGGLE_KEY`.
 
Verify auth works **before** launching the UI:
 
```bash
kaggle kernels list --mine     # should list your kernels, not a 401
```

If no credentials are present, the app still generates the storyboard + images and simply skips the video stage.

python webui/app.py

## Configuration (environment variables)

| Variable | Purpose | Default |
|----------|---------|---------|
| `AIV_PORT` | UI port | `7860` |
| `AIV_INPUT_DOC` | Input document for `prompt_generation.py` (set automatically by the app) | first PDF/DOCX in `input/` |
| `AIV_STORYBOARD` | `storyboard.json` location (set automatically by the app) | `storyboard.json` |
| `KAGGLE_USERNAME` | Kaggle account name (used to build dataset/kernel IDs) | — |
| `AIV_DATASET_WAIT` | Seconds to wait for Kaggle to process the uploaded dataset before the kernel mounts it | `120` |
| `AIV_KAGGLE_TIMEOUT` | Max seconds to wait for the Kaggle GPU run to finish | `14400` (4 h) 

- Per-run artifacts are written under `webui/runs/<timestamp>/` (git-ignored).
- Dataset slug: `ai-doc-to-video-assets`; kernel slug: `ai-doc-to-video-svd`
  (both private, reused/versioned across runs).

## Implementation notes & gotchas
 
These reflect real issues encountered getting the Kaggle stage working end to end:
 
- **GPU pin (T4).** The generated kernel sets `"machine_shape": "NvidiaTeslaT4"`.
  Without pinning, Kaggle may assign a **P100 (sm_60)**, which is incompatible
  with the default PyTorch build (`CUDA error: no kernel image is available`).
  T4 is sm_75 and works.
- **Dataset mount path.** With `kaggle>=1.8.0` the dataset mounts at
  `/kaggle/input/datasets/<user>/<slug>/`, not `/kaggle/input/<slug>/`. The
  generated notebook searches `/kaggle/input/**` for `storyboard.json` so it
  works regardless of the exact mount layout.
- **Dataset readiness.** Kaggle's `dataset_list_files` returns *"This dataset
  type is not supported through the API"* for these datasets, so readiness
  cannot be polled. The app waits a fixed `AIV_DATASET_WAIT` seconds (tiny assets
  process in well under a minute) before pushing the kernel.
- **Status polling.** On some accounts `kernels_status` returns HTTP 500
  repeatedly. The app treats status as a soft hint and decides success by
  **probing `kernels_output` every cycle** for `final_video_*.mp4`; a quiet
  "Still rendering... (working)" heartbeat is printed instead of spamming errors.
- **UTF-8 on Windows.** The local subprocesses run with `PYTHONUTF8=1` /
  `PYTHONIOENCODING=utf-8` (and their output is decoded as UTF-8) so documents
  containing characters like the pi symbol cannot crash the storyboard stage.
 
## Troubleshooting
 
| Symptom | Cause / fix |
|---------|-------------|
| `401 Unauthorized` on any `kaggle` command | Stale/empty token. Run **Expire All Tokens**, create a new one, update `~/.kaggle/access_token` (or `kaggle.json`), and clear any stale `KAGGLE_KEY`/`KAGGLE_API_TOKEN` env vars. |
| `Expecting value: line 1 column 1 (char 0)` | Network/TLS interference (antivirus HTTPS scanning, VPN, proxy) returning an empty body. Confirm `kaggle datasets list` works; try a different network/hotspot. |
| `SSLError` / `ConnectTimeout` to `api.kaggle.com` | Same network interference; the connection is dropped before the response arrives. |
| Kernel fails with `FileNotFoundError: .../storyboard.json` | Dataset not mounted yet — increase `AIV_DATASET_WAIT`. |
| `CUDA error: no kernel image is available` | Landed on a P100; the T4 pin should prevent this (see *GPU pin* above). |
| `Kaggle kernel did not finish within the timeout` | Long render (many scenes) — increase `AIV_KAGGLE_TIMEOUT`. |
| UI stuck on "Still rendering..." after the kernel finished | The video is already in the kernel's Output tab; the next output probe downloads it. Ensure the run is still active and not timed out. |
